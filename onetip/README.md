# 每日一招 · OneTip

> 每天一条和 3 岁左右女儿相处的小方法。打开 App，按一下大按钮，一分钟读完，当天就能用。

## 1. 为谁做、解决什么

- **用户**：上班的爸爸或妈妈，女儿 2 岁 11 个月，可能有老人帮忙带。
- **痛点**：育儿书没空读；公众号和短视频信息多、质量参差、容易焦虑；真正缺的是「今天回家能用的一招」。
- **原则**：一条只讲一件事；100–160 字；有依据；温暖不说教；不卖课、不制造焦虑。

## 2. 核心体验

```
┌──────────────────────────────┐
│  ♡                        ⚙  │
│           她今天              │
│      2岁11个月零7天            │
│                              │
│  ┌────────────────────────┐  │
│  │ 🌦️ 情绪与情商           │  │
│  │ 先接住，再讲理           │  │
│  │ 她大哭时，大脑里负责冷静   │  │
│  │ 的部分暂时下线了……（~130字）│  │
│  │ ▸ 依据                  │  │
│  │ ♡  👍  👎          ⇪   │  │
│  └────────────────────────┘  │
│                              │
│  ╭────────────────────────╮  │
│  │       今日一招          │  │  ← 唯一的大按钮，拇指区
│  │  按一下，看今天怎么陪她   │  │     读完后变成「再来一条」
│  ╰────────────────────────╯  │
└──────────────────────────────┘
```

1. **每天定时推送**（默认早上 8:00，可改）。通知里直接写当天的标题，例如「今日一招 · 情绪与情商：先接住，再讲理」，点开就是这一条。
2. **随时打开，按一下大按钮**：第一次按出今天这条；再按是「再来一条」，不会重复已读的。
3. **一条卡片**：分类、标题、正文、可展开的「依据」（机构 + 链接）、收藏 / 有用 / 不适合 / 分享。
4. **按月龄自动长大**：首次只问生日和提醒时间。孩子每长一个月，内容池自动切换（比如 4 岁前后会出现更多社交、规则类内容）。
5. **不需要账号、不联网也能用**：内容随 App 打包，收藏和已读只存在手机上。

## 3. 功能分期

| 阶段 | 功能 |
|---|---|
| **MVP（本仓库已有骨架）** | 生日 + 提醒时间引导；大按钮读今日一招 / 再来一条；按月龄、分类轮换、不重复的选题；60 天本地通知预排；收藏、有用、不适合（不适合的不再出现）；分享；内容来源页 |
| v1.1 | 锁屏 / 桌面小组件（显示今天的标题）；「今天试了吗？」打卡和一周回顾；深色模式插画 |
| v1.2 | 远程内容更新（App 启动时拉取带版本号的 `tips.bundle.json`，CDN/GitHub Pages 托管，失败就用内置包）；按「有用/不适合」调整分类权重 |
| 以后 | 情境模式（「她正在发脾气」→ 直接给 3 条急救招）；两位家长同步收藏（iCloud）；老人版大字模式；朗读 |

## 4. 内容策略

- **起步 365 条**，一天一条够一年，覆盖 10 个分类：

  | 分类 | 条数 | 分类 | 条数 |
  |---|---|---|---|
  | 语言与沟通 | 40 | 睡眠 | 20 |
  | 情绪与情商 | 45 | 饮食营养 | 25 |
  | 规则与正面管教 | 45 | 健康安全 | 30 |
  | 游戏与学习 | 50 | 社交与入园 | 35 |
  | 生活自理 | 30 | 亲子与家庭 | 45 |

- **每条的结构**：一句「为什么/什么场景」+ 具体做法 + 一句可以原样说的话术或「今天就试」。
- **每条都有依据**：`source_ids` 指向来源清单，`basis` 用一句话写清哪个机构说了什么，App 里「依据」可展开。
- **月龄标签**：每条有 `age_min_months` / `age_max_months`，覆盖 30–54 个月，重点 33–42 个月。
- 完整写作规范见 [`data/SPEC.md`](data/SPEC.md)，`pipeline/validate_tips.py` 会自动检查字数、字段、来源 ID 和近似重复。

## 5. 数据源：从哪里扒、怎么扒、能不能用

数据源质量决定这个 App 的价值，所以分三层，并且严格区分「能改写转载」和「只能参考」。

| 层级 | 例子 | 怎么用 |
|---|---|---|
| **A：政府 / 国际组织 / 学术** | CDC 发育里程碑与积极养育、WHO 5 岁以下活动与睡眠指南、AAP、哈佛儿童发展中心、国家卫健委《3 岁以下婴幼儿健康养育照护指南》、教育部《3–6 岁儿童学习与发展指南》、中国营养学会学龄前膳食指南 | 事实和数字以这里为准。CDC（美国联邦政府作品）和中国国家机关发布的官方文件可改写引用；WHO 多为 CC BY-NC-SA |
| **B：有循证基础的项目与机构** | ZERO TO THREE、Vroom、PCIT、Triple P、Gottman 情绪辅导、Hanen、Raising Children Network、Child Mind Institute | 方法论来源；有版权，只参考、改写、注明出处 |
| **C：经典育儿书与专业科普** | 《如何说孩子才会听》《全脑教养法》《正面管教》《园丁与木匠》《父母的语言》、丁香妈妈 | 只作为思路参考，不转载原文 |

来源清单（每个来源的链接、授权、可抓取性、和 3–4 岁相关的要点）见 [`data/SOURCES.md`](data/SOURCES.md) 和机器可读的 [`data/sources/`](data/sources)。

**采集管道**（`pipeline/`）：

```
sources/*.json ──► harvest.py fetch ──► cache/（只抓 can_adapt 来源，遵守 robots.txt，限速）
                                    │
                                    ▼
                  harvest.py draft ──► data/drafts/*.json（LLM 按 SPEC 起草，自动标出不合规项）
                                    │
                                    ▼  人工审核：准确吗？适合她吗？会不会让人焦虑？
                  data/tips/<分类>.json ──► validate_tips.py --bundle ──► tips.bundle.json ──► App
```

- 有版权的来源（`cite_only` / `book`）**不抓取**，只作为人工写作时的依据并在 `source_ids` 里注明。
- `draft` 的 LLM 配置复用本仓库 `agent_loop.py` 的环境变量（`OPENROUTER_API_KEY` 或 `OPENAI_API_KEY`）。
- 健康与安全类内容上线前最好请儿科医生或学前教育老师过一遍。

**授权上要注意的几点**（详见 `data/SOURCES.md`）：

- **CDC**：美国联邦政府作品，可改写，注明 CDC 即可，不能暗示 CDC 背书。
- **NHS**：Open Government Licence，可改写，注明「Information from the NHS website」。
- **WHO**：CC BY-NC-SA 3.0 IGO，含「非商业」条款。App 如果收费或带广告，只能引用 WHO 的结论，不能改编原文。
- **Vroom**：免费但限非商业使用，改编需要授权。只能作为思路参考，不能改写它的活动卡。
- **AAP / HealthyChildren.org**：版权保留，`llms.txt` 禁止拿来训练模型或大段转载，只能引用要点并链接。
- **AAP 屏幕时间**：AAP 在 2026 年 1 月发布新政策，取代了 2016 年「2–5 岁每天 ≤1 小时」的说法。内容里的 1 小时一律引用 WHO 2019 和教育部近视防控方案，不写成 AAP 的建议。
- **中国国家机关的官方文件**（卫健委、教育部的指南和规范）依《著作权法》第五条不受著作权保护，可改写引用。学会共识、期刊论文和商业平台（如营养学会膳食指南全文、丁香妈妈）仍有版权。

## 6. 选题算法

`TipPicker`（Swift，`ios/OneTip/Logic/TipPicker.swift`）和 `web/picker.js` 规则一致：

1. 标了「不适合」的永不出现。
2. 只选月龄窗口包含孩子当前月龄的；没有就放宽 3 个月、再放宽 6 个月。
3. 先选没读过的；全读过了，从最久没读的三分之一里循环。
4. 分类轮换：从最久没出现的分类里挑，一周下来情绪、游戏、睡眠……各有一条，不会连着五条都是规矩。
5. 同一天用日期做随机种子，所以通知里预告的标题和打开 App 看到的是同一条。

本地通知不能在送达时临时生成内容，所以 App 每次启动都会用同一算法**预排未来 60 天**（iOS 最多 64 条待发通知），把每天的真实标题写进通知。

## 7. 技术架构

- **SwiftUI + Observation，iOS 17+**，无后端、无账号、无第三方 SDK。
- `TipStore`：加载内置 JSON，状态（生日、已读、收藏、反馈、每日分配）存 `UserDefaults`。
- `NotificationScheduler`：`UNCalendarNotificationTrigger` 一天一条，点通知通过 `userInfo["tipId"]` 直达那条。
- 工程用 XcodeGen 生成（`ios/project.yml`），不提交 `.xcodeproj`。
- **隐私**：不收集任何数据，App Store 隐私标签可以填「不收集数据」。

## 8. 目录

```
onetip/
├── README.md                 ← 本文：产品构思
├── data/
│   ├── SPEC.md               ← 内容规范（写作 + JSON 格式 + 来源 ID）
│   ├── SOURCES.md            ← 数据源清单（人读版）
│   ├── sources/*.json        ← 数据源清单（机器读，含授权、抓取方式、要点）
│   ├── tips/<分类>.json       ← 365 条 tip 原稿
│   ├── tips.bundle.json      ← 合并后的发布包（App 内置）
│   └── sources.bundle.json   ← App 用的来源名称和链接
├── pipeline/
│   ├── validate_tips.py      ← 校验 + 打包
│   └── harvest.py            ← 抓取开放来源 + LLM 起草
├── web/                      ← 网页原型（同一算法，手机浏览器就能先用起来）
└── ios/                      ← SwiftUI App 骨架 + 单元测试
```

## 9. 怎么跑

```bash
# 内容：校验并打包
python3 onetip/pipeline/validate_tips.py --bundle

# 网页原型：生成单文件 HTML（web/dist/index.html），手机打开即可用
python3 onetip/web/build.py
node --test onetip/web/picker.test.js

# 扒数据：抓开放来源、起草新 tip（需要 LLM key）
python3 onetip/pipeline/harvest.py fetch
python3 onetip/pipeline/harvest.py draft --limit 20

# iOS（在 Mac 上）
brew install xcodegen
cd onetip/ios && xcodegen generate && open OneTip.xcodeproj
```
